A name means the same wherever you write it: in a ref, in a link, on the command line, and in what
typdoc prints.

> typdoc is still in active development: commands, output and file formats may change between
> releases. What's there is checked by more than a thousand tests on Linux, macOS and Windows. If
> something doesn't behave the way the docs say, please open an issue.

## Install

On macOS and Linux:

```console
$ curl -fsSL https://typdoc.thaitype.dev/install | sh
```

On Windows, in PowerShell:

```powershell
irm https://typdoc.thaitype.dev/install.ps1 | iex
```

Prebuilt for Windows, macOS and Linux, amd64 and arm64. To pin a version or choose where it goes,
see [how to install typdoc](https://github.com/thaitype/typdoc/blob/v0.7.0/docs/how-to/install.md).
`cargo install typdoc` works too.

If you work with a coding agent, add the skill too:

```console
$ npx skills@latest add thaitype/typdoc
```

## What's new

**Every document has a name you can paste anywhere.** Everything typdoc prints now carries `ref`,
beside the `path` it always had:

```console
$ typdoc get story-2/notes/kickoff.md
path: story-2/notes/kickoff.md
ref: story-2:notes/kickoff.md
collection: notes
…
```

`path` is where the file is, for opening it, and has not changed. `ref` is the name that finds the
document from anywhere: in a ref in another document, in a body link, and on the command line. It
is the key for a numbered document (`WF-5`, or `story-2:WF-5` in a project with several
namespaces), and a path with its namespace for any other. In `--json`, every document object gains
a `ref` field.

**The same text means the same document.** `story-2:notes/x.md` is the file `notes/x.md` in
namespace `story-2` in a ref, in a body link and on the command line alike; `./` and `../` are
always read from the file they are written in, as every Markdown reader does.

## Fixed

- **`mv` no longer breaks links in the body.** Moving `notes/b.md` to `notes/c.md` used to turn
  `[one](./b.md#part)` into `[one](c.md)`, and could leave a second link to it on the same line
  unchanged. Every link on the line is rewritten now, keeping its `./` and its `#anchor`.
- A move recorded in one namespace no longer flags a ref to a document with the same key in
  another namespace.

## Before you upgrade

On the command line, most names keep working as before. What changed:

- **A path after a namespace prefix is read from that namespace's folder.**
  `typdoc get story-2:notes/x.md` finds `story-2/notes/x.md`; write `story-2/notes/x.md` if you
  meant a path from the project folder.
- **A namespace prefix is one exact name.** For several namespaces, use `--namespace`:
  `typdoc get WF-1 --namespace 'story-*'` instead of `typdoc get 'story-*:WF-1'`.

`typdoc validate` may report things 0.6.0 did not, each with what to write instead:

- In a collection with `"refBase": "namespace"`, a `./x.md` in frontmatter is now read from the
  document's folder. If you meant the namespace folder, write `story-1:x.md`, or `x.md` with no
  `./`.
- A ref shaped like a key (`XX-1`) is always a key; an absolute path in a ref or a link is reported,
  never followed; a link like `stroy-2:notes/x.md` whose prefix names no namespace is reported
  instead of being skipped as a URL.
- A collection's `match` or a link `ignore` pattern with `?`, `[`, `]`, `\`, `,` or a leading `!`
  is a config error that names the pattern. These patterns used to match nothing, silently. Only
  `*` and `**` are taken.

If you use the `typdoc-core` library, `Error` has a new variant, `NoKey`: see the
[changelog](https://github.com/thaitype/typdoc/blob/v0.7.0/CHANGELOG.md#070---2026-09-29).

Full list of changes: [CHANGELOG](https://github.com/thaitype/typdoc/blob/v0.7.0/CHANGELOG.md#070---2026-09-29).
