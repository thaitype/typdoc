typdoc runs on Windows.

> typdoc is still in active development: commands, output and file formats may change between
> releases. What's there is checked by more than a thousand tests on Linux, macOS and Windows. If
> something doesn't behave the way the docs say, please open an issue.

## Install

On Windows, in PowerShell:

```powershell
irm https://typdoc.thaitype.dev/install.ps1 | iex
```

On macOS and Linux:

```console
$ curl -fsSL https://typdoc.thaitype.dev/install | sh
```

Prebuilt for Windows, macOS and Linux, amd64 and arm64. To pin a version or choose where it goes,
see [how to install typdoc](https://github.com/thaitype/typdoc/blob/v0.6.0/docs/how-to/install.md).
`cargo install typdoc` works too, on Windows as well.

If you work with a coding agent, add the skill too:

```console
$ npx skills@latest add thaitype/typdoc
```

## What's new

**Windows, amd64 and arm64.** Every command works there, reading and writing, with the guarantees
it keeps on macOS and Linux:

- **Two writers never share a namespace.** A lock is released only while it is still this
  process's own, on NTFS and on ReFS, which Dev Drives use.
- **A document keeps its permissions.** When `set` or `mv` replaces a file, the new one keeps the
  old one's access control list and its read-only flag. If the access control list cannot be
  carried, typdoc leaves the document as it was and says why (exit 6).
- **An open document is left alone.** If another program holds the file open without letting it
  be replaced, typdoc changes nothing and tells you:

  ```
  typdoc: notes/a.md: another program has this file open and does not let it be replaced; close it there and run the command again
  ```

- **Ctrl+C cleans up.** The locks typdoc holds are removed before it ends, with exit code
  `0xC000013A`, Windows' own code for a program stopped by Ctrl+C.

**Windows paths on the command line.** In a project at `C:\docs`, run from that folder,
`typdoc get C:\docs\tickets\WF-8.md`, `.\tickets\WF-8.md` and `tickets\WF-8.md` all name the
document `tickets/WF-8.md` does. What typdoc prints, and what
you write inside documents, still uses `/`, the same on every system.

**The PowerShell installer** picks the build for your machine, checks its SHA-256 checksum, installs
`typdoc.exe` to `%USERPROFILE%\.local\bin`, and never changes PATH: if the directory is not on
PATH, it prints the command that adds it. To pin a version:

```powershell
$env:TYPDOC_VERSION = 'v0.6.0'; irm https://typdoc.thaitype.dev/install.ps1 | iex
```

The Windows binaries are not code-signed.

## Before you upgrade

On macOS and Linux nothing changes: the commands, their output and the install script behave as in
0.5.0.

If you use the `typdoc-core` library, `FileId::inode` is now a `u128`: see the
[changelog](https://github.com/thaitype/typdoc/blob/v0.6.0/CHANGELOG.md#060---2026-09-28).
