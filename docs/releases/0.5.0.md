On macOS, typdoc no longer tells you to delete a lock that a running typdoc still holds.

> typdoc is still in active development: commands, output and file formats may change between
> releases. What's there is checked by more than a thousand tests on Linux and macOS. If something
> doesn't behave the way the docs say, please open an issue.

## Install

```console
$ curl -fsSL https://typdoc.thaitype.dev/install | sh
```

Prebuilt for macOS and Linux, amd64 and arm64. Windows is not supported yet. To pin a version or
choose where it goes, see [how to install typdoc](https://github.com/thaitype/typdoc/blob/v0.5.0/docs/how-to/install.md).
`cargo install typdoc` works too.

If you work with a coding agent, add the skill too:

```console
$ npx skills@latest add thaitype/typdoc
```

## Fixed

**A running typdoc's lock is no longer called stale on macOS.** Run two writes into the same
namespace on a Mac, and the second one waits for the first. When it gives up (exit 4), it used to
say:

```
typdoc: lock not acquired: <project>/.typdoc/locks/default.lock is held by pid 2656218 on unknown-host (age 0s); it is not running on this machine: the lock is stale, delete <project>/.typdoc/locks/default.lock
```

while pid 2656218 was still writing. Deleting the lock, as the message said, let two typdoc
processes write one namespace. The same timeout now says:

```
typdoc: lock not acquired: <project>/.typdoc/locks/default.lock is held by pid 2656218 on <this-host> (age 0s); it is running on this machine: wait, or run again with a longer --lock-timeout
```

The hostname and whether the owner is running are now asked of the system on every Unix, instead
of read from `/proc`, which macOS does not have. A lock held by another user's process also reads
as running.

**"Stale" only when it is known.** The message says a lock is stale, with the file to delete, only
when the system answered that no process has the recorded id. When that cannot be known, it says
so and asks you to delete the lock only once you know the process has stopped. There are two new
endings for this:

```
… held by pid 4242 on unknown-host (age 0s); its host is not known, so it cannot be checked from here: delete it only once you know that process has stopped
… held by pid 0 on <this-host> (age 0s); it is on this machine, but whether it is running cannot be checked here: delete it only once you know that process has stopped
```

Taking, releasing and the validity of a lock do not change: only the message does.

Nothing changes for users of the `typdoc` command. If you use the `typdoc-core` library, `acquire`
