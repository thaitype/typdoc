Coded documents can now have readable file names.

> typdoc is still in active development: commands, output and file formats may change between
> releases. What's there is checked by more than a thousand tests on Linux and macOS. If something
> doesn't behave the way the docs say, please open an issue.

## Install

```console
$ curl -fsSL https://typdoc.thaitype.dev/install | sh
```

Prebuilt for macOS and Linux, amd64 and arm64. Windows is not supported yet. To pin a version or
choose where it goes, see [how to install typdoc](https://github.com/thaitype/typdoc/blob/v0.4.0/docs/how-to/install.md).
`cargo install typdoc` works too.

If you work with a coding agent, add the skill too:

```console
$ npx skills@latest add thaitype/typdoc
```

## What's new

**A slug after the key.** Give `new` a slug and the file name says what the document is about:

```console
$ typdoc new WF "Decide lock order" --slug lock-order
path: tickets/WF-8-lock-order.md
…
key: WF-8
```

The key is still `WF-8`. You choose the slug, in any language, and typdoc never makes one up from
the title. Without `--slug`, files are named `WF-8.md` as before.

**Find and refer to it either way.** `typdoc get WF-8` and `typdoc get WF-8-lock-order` name the
same document, and so do refs:

```yaml
blocked_by: [WF-8]               # the key alone never goes stale
related: [WF-8-lock-order]       # easier to read
```

**Rename with `mv`.** `typdoc mv WF-8 tickets/WF-8-lock-ordering.md` keeps the key. Refs written
with the old slug and body links follow the file, and refs by the key alone are left as they are.
If a file is renamed some other way, a ref with the old slug still finds the document, and
`validate` warns under the new rule `refs.slug`.

**Choose per collection.** Set `"slug"` in a collection file to `optional` (the default),
`required` or `none`. `mv --renumber` keeps the slug under the new key.

## Fixed

- A body link that still names a document's old path, written from another folder, is now reported
  as `refs.moved` with the new path, instead of only `body.links`.

## Before you upgrade

Nothing changes until you use a slug, with one exception: a file named like `WF-1-notes.md`, which
`filename.pattern` reported before, now counts as the document `WF-1`. With the default rule
levels, such a project was already failing on that file. The
[changelog](https://github.com/thaitype/typdoc/blob/v0.4.0/CHANGELOG.md#040---2026-09-27) lists
the three cases where a project that passed before can fail after the upgrade.

Full list of changes: [CHANGELOG](https://github.com/thaitype/typdoc/blob/v0.4.0/CHANGELOG.md#040---2026-09-27).
