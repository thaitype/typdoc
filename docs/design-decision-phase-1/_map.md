## Destination

`docs/design.md` plus this map's Decisions so far is enough for `/chief-plan` to write the goals and contracts of the three stories that deliver typdoc v1 without re-grilling: every implementation-level gap in the design is decided, and `docs/design.md` is amended wherever a decision changes what it says.

## Notes

- **Delivery is three stories, not one.** Story 1 is the read core: config, namespaces, schemas, reading and parsing documents, refs, the query language, `validate`, `get`, `list`, `toc`, `refs`, and imports. Story 2 is writing: `new`, `set`, `mv`, `mv --renumber`, locks, state files and the frontmatter round trip. Story 3 is remote schemas: `pull`, `vendor/`, `lock.json` and the fetch adapter. The design's own "Out of scope for v1" list carries over to all three. The reason is that a single story would have the whole design as its goal, and a contract that restates a source of truth is a second copy that starts to disagree with the first with no signal and no way to tell which one is right. Story 3 follows story 2 and does not run beside it, because pins are written under a project lock that story 2 builds; story 1 stands alone. Imports belong to story 1: they find another project on the same machine and resolve refs into it, and involve no network and no `lock.json`. Reads take no namespace lock, so locks belong to story 2 alone. State files are shared: the always-on rule `state.missing` belongs to `validate` and so to story 1, which reads `state/<namespace>.json` and reports the rule, while writing that file is story 2's. Story 1 is an internal milestone and is not released on its own (ticket 20); until story 3 it cannot be tried on a project whose schemas are remote, which limits what can be shown of it. This map and its tickets are not split: they are the decision base for all three stories, and ticket 9 in particular applies to every one.
- **`docs/design.md` is the source of truth** (project rule 6): to deviate from it, amend the doc first. Its original at `~/tmp/typdoc-design/` is a snapshot; this repo's copy is canonical from now on.
- Stack is fixed by `.chief/project.md`: Rust 2024, workspace with `typdoc-core` (lib) and `typdoc` (bin). Decisions here refine it; they do not reopen it.
- The design moves wayfinder-ticket fields (`Type:`, `Status:`, `Blocked by:`) into frontmatter, but the installed `chief-wayfinder` (`v5.canary-2.exp`) still uses inline lines. Tickets in this story use the inline form; typdoc does not manage its own tickets yet.
- Motivating failure: querying prose-formatted records with grep answers wrongly and silently (a status in a heading counted 43 "unanswered" when 21 were). Prefer decisions that make the wrong answer loud.
- Cargo gotchas for later stories: never run two cargo commands in one `target/` at once, and check test counts, not just exit codes.

## Decisions so far

<!-- index: one line per resolved ticket, enough to judge relevance, zoom the link for detail -->

- [YAML frontmatter approach](_tickets/1-yaml-frontmatter-approach.md): read with `yaml_serde` into typed `String` fields; write with `yaml-edit` (exact-pinned, three operations) behind a mandatory reparse guard; `yaml-edit` is two days old, so the guard is load-bearing (decided 2026-09-19).
- [Markdown body parsing](_tickets/3-markdown-body-parsing.md): build on `pulldown-cmark` 0.13.4; cut frontmatter first and parse the body slice; hand-write the line/col mapping and a GitHub-style slugger (decided 2026-09-19).
- [HTTP client for remote schemas](_tickets/6-remote-schema-fetching.md): `ureq` 3.x blocking behind a `Fetch` trait; `typdoc-core` stays runtime-free (decided 2026-09-19).
- [Query grammar](_tickets/5-query-grammar.md): `!=` is exactly NOT `=` and absent things satisfy it (ordering comparisons stay false); escapes are `\` for `,` `*` `\` only, glob is `*` only; names, scope, `$body` and reserved pseudo-fields fixed; `ref.all` and `refby.all` need `.EXPR`; dangling refs found with `ref.any(f).path!=*`; a Grammar block is in the design.
- [Schema format identity](_tickets/8-schema-format-identity.md): typdoc's own JSON format, not JSON Schema; no interop in v1; design wording fixed in three places.
- [Collection definition files](_tickets/12-collection-definition-files.md): one file per collection at `.typdoc/collections/<name>.json` (`match`, `schema`, `refBase`, `validation`, `last`); one `version` in `config.json` covers all typdoc-owned formats; no collection order; overlapping matches are an error; a broken collection file stops the namespace.
- [Counter allocation](_tickets/2-counter-allocation.md): next number = max(highest existing in the collection, the collection's `last`) + 1, written back under the lock; never reused after a delete; the shared `counter` option is removed (one ticket schema, one collection, told apart by `kind`); a coded schema serves exactly one collection; no new file. Where `last` lives is ticket 12.
- [Slug rules](_tickets/4-slug-rules.md): heading slugs follow GitHub's algorithm (Thai kept, `dup-1` collision-aware, empty slugs deduped like any other); link fragments are percent-decoded and compared case-insensitively; `{slug}` is removed from file names, which are never derived from a title.
- [Multiple namespaces in one `.typdoc`](_tickets/13-multiple-namespaces-in-one-typdoc.md): a project (`.typdoc`) holds one namespace `default` or several named by child folders (`namespaces`, one level, `[A-Za-z0-9_-]`); `name` removed from config; `name:` sibling, `name::` import; whole-project import in v1; scope by prefix > `--namespace` > `TYPDOC_NAMESPACE` > cwd, `TYPDOC_DIR` replaces `--dir`; state in `state/<namespace>.json`, locks per namespace; coded docs cannot move across namespaces except `mv --renumber`, with `auto: moves` and `refs.moved`. Amends 2, 12, 7, 5, 4.
- [Column unit](_tickets/11-column-unit.md): `col` counts Unicode scalar values, 1-based (Thai and emoji each 1, tab 1), `line` from the top of the file frontmatter included; no byte offset in `--json` in v1; tests with a Thai line and an emoji line.
- [Link forms checked](_tickets/10-link-forms-checked.md): `body.links` checks inline, image and reference-style links (definitions reported once, with use count; unused ones checked, not in `$body`; duplicate label reported); text that looks like a link but is not (space in a destination ending in a file extension) is reported with a `<…>`/`%20` hint; `[t][ref]` with no definition is not; `mv` keeps each link's written form.
- [Platforms and lock](_tickets/7-platform-and-lock.md): Linux and macOS targeted, Linux supported and macOS not yet a supported claim (Windows build fails clearly); no automatic lock takeover, exit 4 explains, one remover at a time; project lock for pins, `lock.json` without `path`, `vendor/` never pruned in v1; machine file `imports.json` found by `TYPDOC_CONFIG_DIR`, `XDG_CONFIG_HOME`, then the platform default; unset `${ENV}` makes the import absent (`imports.absent`), never an empty string; quoting advice only for shells that were run.
- [Test strategy](_tickets/9-test-strategy.md): one `fixtures/` at the repository root (`valid/`, `broken/<rule>/`, `roundtrip/`), every rule and config error has a fixture, expected values written by hand; `--json` pinned by goldens with assertion files the generator cannot write, an injected clock, no regenerate-all; remote schemas in three layers over plain http; `run(args, deps)` as the only path, with a write seam in `deps` and lint guards that cover test code (`--all-targets`); frontmatter round trip by invariants plus whole files only where the design determines them; signals tested by holding a lock in a shipped binary, no test code in it; spawned processes get an empty environment and a tripwire proxy; shell examples taken from the document with hand-declared values, sh and bash only; a missing state record is `state.missing`, an always-on rule.
- [Exit code split](_tickets/14-exit-code-split.md): exit 1 is bad arguments (a query that breaks the grammar and a key or write ambiguous across namespaces included), 5 is not found, 6 is I/O; a new code only when the caller must act differently, finer detail in an id in `--json`; a well-formed query that matches nothing is 0; project rule 5 points at the design's table instead of copying the range.
- [JSON output](_tickets/15-json-output-shape.md): every command prints an object with a named field for its result; `list` reports `total` and `truncated`; one way to name a document (`path` from the project folder, `namespace`, `key`, `project`); a finding has one shape in the report and in the error object; `validate` is a verdict printed on standard output, with a summary that says its `scope`, `strict` and `audit`; config errors that make checking impossible stop the command with an error object, others are findings; an audit adds `collections`, `uncollected` and `no_frontmatter`; `refs` gives small references with a reason when one does not resolve; `toc` `end` covers the subheadings; a value in the output is a fact about the document, never about the command; every array declares its order.
- [Path arguments](_tickets/16-path-arguments.md): a path argument that is absolute or begins with `./` or `../` is on disk and may name the project; any other is relative to the project folder; a key is told from a path by its form, never guessed; a table gives the string that names a document, and a test feeds every printed name back.
- [Schema drift](_tickets/17-schema-drift.md): `validate --schemas` checks that each qualified `target` names a schema that exists, under `schema.valid`; a renamed field cannot be checked ahead of time and is a loud error when a query runs.
- [Unparsable frontmatter](_tickets/18-unparsable-frontmatter.md): a new always-on rule `frontmatter.parse`; a block that cannot be parsed is not an absent block, and no other rule is evaluated for that file.
- [Flags with arguments](_tickets/19-flags-with-arguments.md): `--schemas` and `--audit` with key or path arguments is exit 1.
- [Story 1 and remote schemas](_tickets/20-story-1-and-remote-schemas.md): story 1 is an internal milestone, not released alone; a remote schema with no pin is `config.schema-unpinned` until story 3.
- [Cost of a run](_tickets/21-cost-of-a-run.md): no cache, no promised figure, measured once the index exists; `total` on `list` is a chosen cost.
- [Case in paths](_tickets/22-case-in-paths.md): paths are compared with their case on every platform; keys cannot differ only in case; no portability rule in v1.

## Not yet specified

- The `--json` shapes of `new`, `set` and `mv` (story 2) and of `pull` (story 3). The shapes of the read commands and of the error object are decided (ticket 15).
- From ticket 9, for the contract: what an interrupted write leaves behind (the design promises the target file is whole and says nothing about a temp file); the instant between creating a lock file and registering it for cleanup; an interrupt that arrives while the process is working and not waiting; and that every command takes its locks through one acquisition path, which the signal tests depend on (if that cannot hold, ticket 9 names the fallback).
- Distribution and versioning of the tool itself (`cargo install`, release binaries, config `version` upgrade path). Also open there: whether the test suite must run from a published package. Fixtures and examples sit at the repository root, outside every crate's package root, so a package's `tests/` cannot find them (checked with `cargo package --list`); choosing between excluding `tests` from packages and moving fixtures inside a crate belongs to this decision.
- A published meta-schema (JSON Schema describing typdoc's own schema files) so editors can complete `schemas/*.json`; no one has asked for it yet.
- Exact argument shape of `mv --renumber` (how the destination namespace is named) and whether it is atomic across two namespaces when a write fails midway; belongs in the contract.
- From ticket 7, for the contract: the crate for catching interrupt signals; zsh is not in the quoting list, because no test runs it and it is not installed where this was decided; it returns together with a test that runs it, and until then the most common way to run typdoc on macOS is not a covered shell (a known gap); whether `imports.absent` should fire for an unresolved import that nothing refers to.
- From ticket 9, for the contract: tests that run the real HTTP adapter inside the test process are not covered by the offline tripwire, and nothing checks that they connect only to listeners they create.
- macOS: not yet a supported platform, because no run on macOS has shown it; a known gap that closes when a run exists (ticket 9). The case of paths is decided (ticket 22); a `mv` that changes only the case is settled in story 2.
- Parked, not waiting on an answer and blocking no ticket: a macOS runner, and running the public-text gate (`scripts/check-public-text.sh`) in CI or a hook. Today the gate runs only when someone remembers, so it is a habit, not a gate. Not raised again until someone takes it up.
- For the contract: the error id of a write rejected by the re-read check; and proving `yaml-edit` on anchors and tags in the prototype.
- For story 1's contract: what position a `frontmatter.parse` finding carries for the errors where the YAML reader gives none (a second YAML document in the block) or the start of the mapping (a duplicate key); the finding must not read as more exact than the reader (ticket 18).
- Measure the cost of a run once the index exists; v1 promises no figure (ticket 21).

## Out of scope

- Everything on the design's own "Out of scope for v1" list: editing body sections, SQL queries, saved query aliases, multi-hop ref traversal, imports of imports.
- Changing the `chief-wayfinder` or typmem skills to use typdoc: that work belongs to their repos, after typdoc exists.
- Migrating any existing registry (e.g. K-Care's `.jsonl` registers) onto typdoc.
- Checking only the schema files named on the command line, for a pre-commit hook: it is a different feature from combining `--schemas` with arguments, not in v1, and may be added later (ticket 19).
