# Testing Decisions

A good test observes what a person or a program can see: stdout, stderr, exit codes, and files a
command leaves on disk. A check that cannot fail is not evidence, so each one below is shown able
to fail before it is trusted to pass. Expected values are written by hand; goldens are not
generated by running the tool and eyeballing the result.

## Design.rs's replacement

The three tests that read `typdoc_testkit::design::*` today — `frontmatter.rs`'s
`every_shape_the_design_names_as_lost_is_held_by_some_document_in_the_corpus`, `rules.rs`,
`coverage.rs` — are rewired to read the four catalog documents through the new central helper,
keeping the same property each already has: a rule, command, exit code, or loss row added to the
catalog is a row the matching test reads too, so the test and the catalog cannot silently drift
apart. Shown able to fail the same way `design.rs`'s own tests show it today: add an id to a
catalog document with no matching code, or add code with no matching catalog entry, and the test
that reads it goes red. This is re-verified after the rewrite, not assumed to still hold because
the old tests held it.

The central helper's `body-type` validation is tested directly, not only through the three
existing call sites: a catalog document missing the `body-type` field, one with an unrecognized
value, and one whose body is not valid JSON each fail with a distinct, readable error — none of
the three is silently accepted as if it were a plain document. A document under
`docs/design/catalog/` with an unrelated `body-type` value (were one ever added) is read
correctly by the same helper, proving the dispatch is on the field and not hard-coded to `json`.

## The stack-overflow fix

A regression test, run on a thread built with `std::thread::Builder::stack_size` set explicitly
small (not the process's default, and not this machine's, so it fails the same way on any
machine), against a synthetic one-way chain of at least 200,000 `acyclic`-referenced documents
with no cycle. Shown red against `visit`'s current recursive form before the rewrite lands, and
green after — both runs captured in the ticket's own report, not only asserted. The existing four
`cyclic_nodes` unit tests (two-node cycle, self-loop, no-cycle chain, cycle-with-a-tail) are
re-run unchanged after the rewrite: same inputs, same expected output, because the algorithm's
semantics do not change, only where its call stack lives.

Because a real stack overflow aborts the whole test binary rather than failing one test, the
regression test's failure is confirmed to appear as a failure in `scripts/test.sh`'s own output
— not as a harness that exited early and looked merely short. This is checked once, by hand,
when the test is first written (before the fix, to see it fail the intended way), not on every
run.

## CI

CI wiring itself isn't testable by a unit test — the evidence is a demonstration, done once and
recorded in the ticket's report: on a throwaway branch, one commit each that breaks `scripts/test.sh`
(a failing assertion), `cargo fmt --check` (an unformatted line), and `cargo clippy` (a
`#[allow]`-free lint hit), pushed and confirmed red in the CI run for each, then the branch
deleted. Only after all three are shown able to fail does a clean push to `main` count as
evidence the workflow works, rather than evidence a step silently did nothing.

## Text output

Each command gains a hand-written golden for its new text-mode shape, built the same way story
2's write-command goldens were (an injected clock where a shown value would otherwise be
non-deterministic): `get`, `set`, `new` (both forms), `toc`, both forms of `mv`, and `list`'s new
header row. Every golden is read for the field-names principle directly — no line in any of them
is a bare value with nothing naming it — not asserted structurally by a shared helper, since the
shapes differ enough (a labeled block vs. a table) that one generic check would either miss a
real violation or reject a valid table row.

`mv`'s goldens (both forms) cover: a move that rewrites at least one ref (`rewritten:` shows the
right count of refs and documents); a move that leaves at least one ref unrewritten (its own
count, and the project/document/field/written-form line matches an actual unrewritten case, not
a placeholder); and a clean move (`rewritten: 0 refs in 0 documents`, `unrewritten:` shows
`none`). `mv --json`'s golden is rewritten for the same three cases, asserting `rewritten`'s full
list — each entry's `document`, `field`, `before`, and `after` — matches what the text summary
only counted, and that every field `mv --json` printed before this story still does.

`list`'s existing golden tests are updated for the header row, and a case with an empty result is
kept (or added) to assert the header is genuinely absent there, not merely present-but-empty.

The error-path fix (every `failure`/`failure_text` call site's hard-coded `true`, replaced with
each command's real `json` flag) is tested per command: for at least one representative error
case in `new`, `get`, `set`, `refs`, `toc`, and `mv`, the stderr without `--json` is asserted to
be `typdoc: <message>\n` — plain text — and not the `{"error":...}` object. `typdoc new` with a
target that is neither a valid code nor a path is the case already confirmed reproducible before
the fix; it is kept as one of these tests specifically because it is the one already shown
failing today, so the fix is proven against a known-red case, not only against new ones invented
to match the fix.

## What this story does not test

- Whether `date`/`datetime` share `number`'s `f64`-exactness limit — not measured unless a ticket
  is built for it; no test asserts a boundary that was never measured.
- Anything under remote schemas, per the goal's Out of Scope.
- No `--verbose` flag exists, so there is nothing to test not existing — its absence is a design
  decision (M-10h), not a gap.

## Differences between the design and the binary

Closing this story's work removes `design.rs` from `UNIMPLEMENTED_*`-style tracking only in the
sense that nothing tracks it any more — it is not a gap being closed, it is code being deleted.
The stack-overflow fix and the six previously-gated text-output commands are the story's own
"was broken, now isn't" list; each is confirmed fixed by the tests above, not by the absence of a
complaint.
